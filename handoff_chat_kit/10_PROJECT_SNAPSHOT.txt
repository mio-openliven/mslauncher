What it is:
MSLaunch is a PyQt6 Minecraft launcher with project modes:
- MSLaunch / independent
- MS Nuckem / protected modpack flow
- VibeCraft placeholder only

Core files:
- gui.py: launcher UI, project switcher, reports, password gates, update button, admin panel view
- launcher_core.py: Minecraft version install/launch, mod sync, process handling
- launcher_update.py: APP_VERSION and update notice helpers
- panel_client.py: panel API calls for active builds, launcher updates, reports
- launcher_config.json: default local config template
- MSLauncher.spec: PyInstaller launcher build
- setup_bootstrapper/MSLaunchSetup.cs: .NET setup bootstrapper
- bootstrapper.py: Python bootstrapper

Current important state:

Business rules:
- MSLaunch/independent: Mods/Game Folder opens the game/profile folder.
- MS Nuckem: Download Mods must go through build password gate and sync.
- Each mod build can have its own password.
- Nukem uses its slideshow backgrounds and Nukem-only social links.
- VibeCraft remains disabled/placeholder.
- Do not launch Minecraft during automated tests.

Panel direction:
- Panel is intended to become priority source for builds, passwords, reports, launcher updates, backgrounds, logos, news.
- GitHub remains fallback source.
- Reports from Nukem should go to Nukem/admin panel.
- MSLaunch generic reports may go to GitHub/local reports if implemented safely.

Known pain points:
- Launcher UI still needs cleanup and consistency.
- Update/installer flow has had hash/package mismatch bugs.
- SmartScreen/Defender warnings are expected for unsigned new exe; real fix is signing/reputation, not code tricks.
- Mascot animation experiments are prototypes only and should not be mixed back into launcher until assets are production-ready.
