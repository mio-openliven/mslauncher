# Что допилить после передачи

Этот список не является blocker для текущей demo-передачи. Он нужен, чтобы после первых тестов с клиентом выбрать следующий этап без хаоса.

## Срочно после демо

- Прогнать `MSLauncher.exe` на чистой Windows без Python.
- Проверить реальный HTTPS-хостинг клиента:
  - `https://domain.com/mslauncher/build.json`;
  - `https://domain.com/mslauncher/manifest.json`;
  - ссылки на реальные файлы из `mods`, `config`, `resourcepacks`.
- Проверить реальный запуск Minecraft `vanilla` и `fabric` на целевой версии сборки.
- Проверить сценарии ошибок руками:
  - нет интернета;
  - нет Java;
  - старая Java;
  - hash mismatch;
  - недоступный файл из manifest.
- Подготовить один контрольный server_pack клиента и зафиксировать рабочую команду генерации.

## Для нормального MVP

- Bundled Java или безопасная автоустановка Java.
  Сейчас лаунчер только ищет установленную Java и объясняет ошибку.
- Более понятный UI настроек:
  - отдельное окно/панель с `source_key`;
  - выбор RAM;
  - путь к Java;
  - кнопка открытия папок профилей и отчетов.
- Улучшенный crash report export:
  - кнопка “Скопировать отчет”;
  - сбор `latest.log`, последнего crash report и системной информации в один zip/txt.
- Лимиты размера загрузок:
  - максимальный размер одного файла;
  - максимальный размер всей сборки;
  - проверка `Content-Length` до скачивания;
  - понятная ошибка при превышении лимита.
- Проверка свободного места на диске перед синхронизацией.
- Более аккуратный progress по общему размеру сборки и отдельному файлу.

## Для коммерческого релиза

- Подпись `build.json` / `manifest.json`.
  HTTPS защищает канал, но не доказывает, что manifest выпущен администратором сборки.
- Подпись Windows exe или нормальный release pipeline, чтобы снизить предупреждения SmartScreen/антивирусов.
- Автообновление самого лаунчера с подписью версии.
- Microsoft auth / online-mode, если проект будет использоваться не только как private/offline launcher.
- Более строгая модель доверия для remote config:
  - pin домена;
  - pin публичного ключа подписи manifest;
  - история версий сборки.
- CI-проверки на GitHub:
  - smoke tests;
  - build packaging smoke;
  - генерация тестовой сборки.
- Версионирование релизов:
  - changelog;
  - номер версии в GUI;
  - архивы сборок.

## Идеи позже

- PyArmor/обфускация как защита от новичков.
  Это не полноценная безопасность, но может снизить риск простого копирования исходников.
- Несколько серверных сборок с разными `source_key`.
- История последних ошибок внутри UI.
- Импорт/экспорт личных профилей.
- Кэширование скачанных файлов между профилями без потери безопасности.
- Локальный preview manifest перед загрузкой на хостинг.

## System Check

System Check не является blocker текущей передачи.

Не реализовывать его как “антивирус”. Лаунчер не должен автоматически удалять файлы TLauncher, KLauncher, других лаунчеров или любые чужие программы.

Допустимый безопасный вариант позже:

- первое мягкое уведомление;
- диагностика конфликтующих папок/Java/путей;
- запись результата в лог;
- кнопка “Открыть инструкцию”;
- пользователь сам принимает решение, что удалить или изменить.

Любые автоматические удаления вне managed server-профиля запрещены.
