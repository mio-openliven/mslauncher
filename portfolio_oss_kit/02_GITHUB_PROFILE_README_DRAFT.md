# Hi, I'm Li2Fox

I build small, practical tools for Minecraft communities and learn software engineering by shipping things that people can actually use.

Most of my work starts from a real server problem: players need a simpler launcher, admins need safer modpack delivery, a server needs a small gameplay plugin, or a migration needs less fragile scripts. I use Codex heavily as a learning partner and engineering assistant, then keep the parts that work, document them, and turn them into MVPs.

## What I am working on

- **MSLaunch** - a Minecraft launcher and modpack synchronizer with project profiles, update flow, reports, and protected modpack access.
- **MS Nukem client releases** - public client delivery for a private server project.
- **KingOfTheHill / koth-plate** - a small Paper plugin for capture-point gameplay with Vault rewards.
- **TitanForge Engine** - experimental tooling for cinematic Minecraft map generation workflows.
- **VibeCraft infrastructure experiments** - authentication, proxy migration, and server maintenance tooling.

## How I build

I prefer small working steps:

- ship an MVP;
- test it with real users;
- document what works;
- keep private things private;
- publish reusable parts when they are safe and useful.

Some repositories are public learning projects. Others stay private because they contain server-specific logic, customer work, private deployment details, or unfinished experiments.

## Author note

These projects are made in the spirit of learning, practice, and helping my own community. They are not always polished commercial releases. If something here helps you, feel free to use it, open an issue, or suggest an improvement.

My goal for the next year is simple: keep building with AI-assisted engineering, become more disciplined, and turn rough ideas into reliable tools.
